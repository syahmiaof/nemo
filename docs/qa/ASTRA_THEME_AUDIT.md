# Three-theme audit

Theme chooser exists at Settings → Appearance. In a disposable demo context, Midnight, Daylight and Aurora selection each changed `documentElement.dataset.theme` and persisted after reload (`artifacts/audit-measurements.json`). A separate 30-route mobile pass covered Overview, Projects, Project Detail, Tasks, Calendar, Academics, Goals, Goal Detail, Insights and Settings in all three themes (`artifacts/theme-route-results.json`); no route-level overflow was observed. On the later `19c9bfb` revision, the intentionally replayed welcome overlay was dismissed before those route screenshots.

| Theme | Observed result | Defect/limit |
|---|---|---|
| Midnight | Core shell, panels, charts and navigation retain navy/peach/mint hierarchy. | No confirmed palette regression in captured screens. |
| Daylight | Core pages, charts and primary controls mostly switch to light surfaces. | **N4C-01 P1:** Ask Nemo panel remains `rgb(11,19,34)` while body text resolves to dark Daylight tokens. Approximate primary-on-panel contrast is **1.04:1**, secondary-on-response-tile **1.57:1**; message content is visibly unreadable in `ask-nemo-daylight-390.png`. **N4C-03 P2:** Settings Midnight/Aurora preview cards use dark backgrounds but global `.text-white` remapping darkens their labels; sampled label/card contrasts about **2.77:1** and **1.62:1**. See `interaction-results.json` and `daylight-settings-full-390.png`. |
| Aurora | Distinct deep-green accent and ambient backdrop persist across SPA route changes; readable main foreground in captured overview/settings. | Browser marker stayed on the same backdrop node across SPA navigation. Computed pseudo-element durations were 24s/30s, then 0s/0s under OS reduced motion and the in-app preference (`artifacts/aurora-probe.json`). No frame-time/GPU profiler trace or physical mobile performance result, so performance claim remains open. |

Likely N4C-01/N4C-03 cause: `src/index.css:722-731` remaps every `.text-white` to Daylight's dark `--text-primary` without respecting dark sub-surfaces. `src/features/assistant/AskNemoDrawer.tsx:159-233` hardcodes navy surfaces; `src/features/settings/SettingsPage.tsx:378-489` does likewise for dark preview cards. Treat these as surface-scoped token defects. An acceptance pass must inspect the actual computed text/background pairs in all three themes, not only check that `data-theme` changed.
